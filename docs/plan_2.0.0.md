# 2.0.0 无线设备电量适配开发计划

目标版本为 2.0.0；1.0.0 保留为首个稳定 Release，不移动已有标签。
开发期间使用 2.0.0.dev2，正式发布前才切换为 2.0.0。

## 第一阶段：Windows 通用属性

- 扩展扫描范围至蓝牙、USB、HID，校验属性类型、长度和 0–100 范围。
- 统一查询入口，为后续数据源保留独立接口。
- 用实例 ID 去重，避免两台同名设备被合并；暂不按容器合并，共用接收器的鼠标和键盘可能属于同一容器。
- 正常无结果不启动耗时 PowerShell；仅 API 失败时回退，回退也只查询当前存在设备。
- UI 改为无线设备描述，保留后台刷新及低电量提醒。
- 验收：无设备、同名设备、异常数据、来源失败测试；本机扫描及蓝牙回归。

## 第二阶段：标准 HID

- 枚举 HID 接口，记录 VID/PID、接口路径、容器、产品名称与报告能力。
- 使用 Windows HID preparsed data 检查 Usage Page 0x06 / Usage 0x20。
- 按描述符的 Report ID、长度、逻辑范围读取并解析 Feature / Input 报告，不能假定电量字节位置。
- 对 Null 值和越界值返回未知，不伪造 0%；不能将有线 USB 自动标记为 2.4G。
- HID 调用放入可终止的独立工作进程并设总超时，避免驱动卡住刷新。
- 验收：描述符和报告样本测试、拔插、休眠、占用、超时，以及至少一台标准 HID 电量设备验证。

## 第三阶段：厂商协议

- 提供按 VID/PID、接口和协议版本匹配的适配器注册机制；不向未知设备试发命令。
- 先根据实机和公开协议确定首个支持型号，再实现适配器。
- 每个接收器按设备槽位区分键盘/鼠标，保存稳定身份、充电状态和数据来源。
- 兼容清单记录型号、协议来源、固件、验证结果；只有实机验证后才标记支持。
- 验收：真实/脱敏协议样本、错误响应、断连、多设备、官方软件同时运行和至少一台实机。

## 发布条件

- 三阶段分别验收；明确列出已支持型号与未覆盖协议。
- 蓝牙回归、Win+D、启动绘制、低电量提醒、拔插和长时间刷新验证。
- 干净环境打包，双击 EXE 验证 Qt 依赖、版本信息和启动时间。
- 更新兼容性说明及 changelog，再创建新的 v2.0.0 Release。

## 实施记录

- 第一阶段代码已实现：独立 Windows 数据源、USB/HID 扫描、实例去重、错误回退和 UI 文案。
- 本机扫描读取到蓝牙 AJ159 APEX 电量 58%；本次扫描无 USB/HID 电量属性结果。
- 当前 Python 缺少 PySide6，尚未执行 GUI 与 EXE 回归；不将第一阶段标为全部验收完成。
- 本机枚举发现 USB VID_19F5 / PID_6130 的多个 HID 接口；设备具体型号和电量协议尚待确认。
- 第二阶段代码已实现：Windows 原生 HID 枚举、能力解析、Feature/Input 读取、范围校验、独立进程超时隔离及诊断导出。
- 第三阶段代码已实现：VID/PID/接口白名单注册、Arctis 7 系列电量查询、Logitech HID++ 2.0 1004/1000 功能发现和多槽位读取。
- 已加入合成协议样本、错误匹配、离线槽位、超时回收及原生 ABI 测试。首批适配器的实机验证由后续设备测试完成；仍不能宣称全品牌兼容。
- 具体支持范围与已知限制见 `compatibility.md`。GUI、干净环境 EXE 和真实 2.4G 电量的验收尚未完成。

参考：[Windows HID API](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/hid-api)、[HidD_GetFeature](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidsdi/nf-hidsdi-hidd_getfeature)。
